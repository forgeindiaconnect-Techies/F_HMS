1. Executive Summary

RestaurantHub is an enterprise-grade multi-tenant SaaS platform built to optimize restaurant operations, digital ordering, and administrative support services. The codebase employs a decoupled, secure REST API backend coupled with modern single-page-application (SPA) dashboards, guaranteeing low latencies, high scalability, and clean modularity.

2. Core Technology Stack

Frontend Stack

React / Vite

Backend Engine

Node / Express

Database Store

MongoDB Atlas

  • Frontend Layouts: Tailored styling using Vanilla CSS grids and Tailwind CSS, responsive mobile-first viewports, and Lucide React icons.
  • Security Framework: Password hashing via bcrypt, stateless sessions via JWT tokens, and CORS policies gated at the router level.
  • Deployment Nodes: Production frontend served via Vercel Edge Server; production API server handled by Render.

3. Portal Workflows

The platform features four user-facing interfaces with strict access controls:

  • SaaS Landing Portal: Provides product features, pricing matrices, FAQs, and a lead capture contact form with real-time phone number parsing.
  • Super Admin Dashboard: Administrative dashboard tracking SaaS MRR, restaurant verification status, public leads capture, and tenant tickets.
  • Restaurant Merchant Portal: Restaurant Admins manage menus, branches, waitstaff, cashier registers, kitchen preparation status, and digital QR codes.
  • Diner Live Telemetry Flow: Dynamic customer ordering page featuring animated order-prepared routing progress bars and live ETA updates.

4. Core Schema Specifications

The database relies on MongoDB document relationships mapped using Mongoose ODM validation models:

User Document Schema

UserSchema = { _id: ObjectId, name: String, email: String, // Unique Index password: String, // Hashed role: Enum['SuperAdmin', 'RestaurantAdmin', 'Chef', 'Waiter', 'Cashier', 'DeliveryPartner'], restaurantId: ObjectId, // Reference to Restaurant Document branchId: ObjectId // Reference to Branch Document }

Inquiry Document Schema (Leads)

InquirySchema = { _id: ObjectId, name: String, email: String, phone: String, restaurantName: String, subject: Enum['Sales', 'Support', 'Demo', 'General'], message: String, status: Enum['New', 'In Progress', 'Resolved'] (Default: 'New'), createdAt: Date, updatedAt: Date }
